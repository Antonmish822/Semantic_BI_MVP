# План тёмного редизайна CRM Pulse на React

Перенести основную навигацию в левую колонку и оформить семь React-страниц в тёплых тёмных тонах. Из Autumn взять вертикальный список разделов, компактные карточки с крупными значениями, тонкие разделители и тёплый акцент на графиках. Применить эти приёмы к текущим показателям, графикам и действиям CRM Pulse. [Autumn CRM Dashboard Insight на Dribbble](https://dribbble.com/shots/27554333-Autumn-CRM-Dashboard-Insight)

Объём работ ограничен компоновкой и оформлением React. Переиспользовать текущие URL, фильтры, сценарии обновления, API, правила доступа и браузерное хранилище. Тёмная палитра применяется при открытии React-приложения, без настройки темы.

## 1. Левая панель и компоновка страниц

- Вынести `PageNav` в общую оболочку вокруг текущих страниц. Слева разместить «Пульс сделок», «Пульс лидов», «Сотрудники», «AI Agent», «Запросы» и «Инструменты» в текущем порядке. Справа разместить заголовок и действия страницы, ниже её содержимое. Оставить один `<main>` на страницу и использовать `aria-current="page"` для действующей ссылки. [Точка входа React](../frontend/src/main.tsx), [компоненты навигации и заголовка](../frontend/src/app/DashboardChrome.tsx)
- На страницах инструментов разместить «Онтология» и «Запросы» вложенным списком под «Инструментами». Выделять текущий подраздел внутри списка. Кнопки «Сделки / Сводки», «Лиды / Сводки» и «Сотрудники / Сводка» оставить над соответствующими данными с текущими `aria-pressed` и `aria-controls`. [Навигация инструментов](../frontend/src/app/ToolsNav.tsx), [пример переключателей на странице сделок](../frontend/src/app/DealsPage.tsx)
- Взять за исходную ширину панели 224 px при viewport от 1120 px и 168 px в диапазоне 768–1119 px. В обоих случаях показать полные подписи. При ширине меньше 768 px использовать левую колонку шириной 64 px, с различимыми иконками и полными доступными именами ссылок. Целевая зона нажатия каждой ссылки — 44 × 44 px. Текущий пункт выделять фоном и вертикальной меткой. На низком экране панель должна прокручиваться, чтобы нижние ссылки оставались доступны.
- Правой колонке задать `min-width: 0`. Число карточек в строке определять по ширине области данных. На телефоне складывать карточки и редакторские панели в одну колонку, переносить действия шапки и ограничивать горизонтальную прокрутку контейнерами широких таблиц и блоков кода.

## 2. Тёмная палитра и применение к экранам

Ввести семантические CSS-переменные в React-стиле и подключить его после базовой таблицы стилей. Ограничить тему корнем React-страницы и указать `color-scheme: dark` в CSS и метатеге React. Общий `static/styles.css` используется также страницами, которые Gateway отдаёт в режиме отката. [Текущая точка входа React](../frontend/src/main.tsx), [HTML React](../frontend/index.html), [раздача статики в Gateway](../backend/services/gateway/app.py#L220)

| Назначение | Предлагаемые цвета |
| --- | --- |
| Фон приложения, боковая панель, карточки | `#181513`, `#1F1A17`, `#24201D` |
| Поля и приподнятые поверхности | `#2D2622` |
| Основной и вторичный текст | `#F4EAE1`, `#B6A69B` |
| Акцент, фон активного пункта, обводка фокуса | `#F4A574`, `#3A281F`, `#EDBC95` |
| Декоративные разделители и границы полей | `#403630`, `#8B786C` |
| Риск, предупреждение, успех, второй ряд графика | `#F07D83`, `#F1C66E`, `#87C5A9`, `#A9ACF4` |

1. На «Пульсе сделок», «Пульсе лидов» и «Сотрудниках» оформить текущие показатели, списки и графики. Использовать крупные табличные цифры, тонкую сетку и читаемые подписи осей. Сохранить данные и шкалы графиков. Для двух рядов использовать подписи легенды и различимый рисунок линий. Красные сделки и лиды выделять вместе с текстовыми метками.
2. Распространить оформление на AI Agent, каталог, отладчик и онтологии. Обработать формы, Markdown, таблицы, блоки SPARQL и JSON, редактор Turtle и диалоги. Проверить заданные напрямую цвета, включая `fill` и `stroke` графиков, фон нативных полей и подложку диалога. Привести существующие состояния загрузки, пустого результата, ошибок, наведения, фокуса и недоступности к той же палитре. [Базовые стили](../frontend/static/styles.css), [компонент графика](../frontend/src/app/TrendChart.tsx)

## 3. Автоматические тесты

| Проверка | Что должно пройти |
| --- | --- |
| Навигация | Playwright открывает шесть пунктов и оба подраздела инструментов. На прямых URL и старых алиасах, после перезагрузки и переходов «Назад» и «Вперёд» активные пункты соответствуют странице. Навигация доступна через `Tab`, `Shift+Tab` и `Enter`. |
| Компоновка | На 1440, 768, 390 и 320 px панель находится слева, кнопки доступны, а ширина документа укладывается во viewport. Широкие таблицы и длинный код прокручиваются в своих контейнерах. Диалог удаления помещается на экране, закрывается по `Escape` и возвращает фокус кнопке. |
| Поведение | Существующий набор Playwright покрывает фильтры, сводки и обновление, сессию чата, запуск и публикацию запросов, операции редактора онтологий. Добавить проверки в сценарии, которых касается новая компоновка, например скачивание из широкой таблицы на телефоне. |
| Скриншоты | Заменить попиксельное сравнение React с legacy на `toHaveScreenshot` с эталонами тёмного React. Снимать панель вместе с содержимым. Использовать текущие моки API, фиксированное время, отключённые анимации и дождаться данных. Снять семь страниц на 1440, 768 и 390 px, дополнительно — сводки с графиками, ответ чата с таблицей, результат запроса и диалог. Создать эталоны в том же окружении Chromium, в котором их проверяет CI. Проверки поведения из текущего сравнения перенести в E2E, если они ещё не покрыты. [Существующий тест сравнения](../frontend/e2e/app.spec.ts#L503) |

Команды из корня репозитория для прогона после реализации.

```bash
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run test:unit
(cd frontend && npx playwright install chromium)
npm --prefix frontend run test:e2e
python tests/compose/react_smoke.py
```

Локальный прогон сохраняет скриншоты в `frontend/test-results`. В CI переменная `PLAYWRIGHT_COMPARE_SCREENSHOTS=1` включает сравнение с эталонами в контейнере Playwright, версия которого зафиксирована в workflow. [Проверки React в CI](../.github/workflows/react-web.yml)

## 4. Ручная приёмка

- В браузере проверить все семь страниц на 1440, 768 и 390 px. На 320 px и при увеличении масштаба проверить крайние случаи с длинными русскими заголовками, URI, графиками, редакторами, таблицами и диалогами. С клавиатуры пройти от боковой панели до действий и полей страницы. Убедиться, что фокус виден и не скрывается при прокрутке.
- Проверить контраст в действительно отрисованных состояниях, включая ссылки, вторичный текст, подписи графиков и элементы на фоне активного пункта. Требования — 4,5:1 для обычного текста и 3:1 для крупного текста, значимых границ элементов и графических данных. Проверить, что активный раздел и статусы различимы по форме или тексту. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- На собранном Docker-образе выполнить smoke-проверку Gateway в режимах `GATEWAY_WEB_APP_ENABLED=1` и `0`. Проверить вход и возврат на исходный URL, прямые ссылки и загрузку статики. В браузере подтвердить, что React открывается в тёмной теме, а режим отката отдаёт исходную светлую страницу. Проверить консоль при открытии и переходах. [Smoke-сценарий Gateway](../tests/compose/react_smoke.py)

Редизайн готов к приёмке, когда боковая панель и тёмная палитра работают на всех семи страницах, визуальные эталоны проверены, а сценарии React и отката проходят в собранном образе.
