# Дорожная карта переноса интерфейса CRM Pulse на React

Связанный документ — [дорожная карта перехода на микросервисы](microservices_implementation_roadmap.md).

## Цель и границы

Перенести отрисовку, состояние и обработку действий всех семи страниц в React. Сохранить вёрстку, стили, тексты, графики, пользовательские сценарии, URL и данные, которые уже хранятся в браузере. React обращается к существующим API через Gateway. Смена API, маршрутизации микросервисов и серверных вычислений выходит за рамки этого плана.

Сейчас React строит интерфейс из HTML в `static/`, после чего [загрузчик](../web/src/app/pages.ts) запускает legacy-скрипты. [Текущий набор Playwright](../frontend/e2e/app.spec.ts) включает девять сценариев, в том числе сравнение скриншотов семи страниц после загрузки на одинаковых данных. Для миграции нужен отдельный эталон состояний после действий пользователя.

Переносить по одной странице. Для готовой страницы React владеет всем её DOM и состоянием. Страницы, которые ещё переносятся, загружаются через действующий адаптер. Обычные ссылки, прямое открытие URL и история браузера сохраняются. При переносе разметки в JSX использовать текущий `frontend/static/styles.css`, CSS-классы, порядок элементов и доступные названия элементов управления.

## Этапы реализации

### 0. Зафиксировать эталон

- Снять скриншоты legacy в Chromium на ширинах 1440, 768 и 390 px. Зафиксировать входные данные, часы, часовой пояс, шрифты и настройки браузера. Сохранить отдельно эталоны первого экрана и ключевых состояний после действий.
- Описать запросы, которые запускаются при входе, смене фильтра или вкладки, раскрытии списка, ручном и периодическом обновлении. Зафиксировать различия между нулём, пустой выборкой, отсутствующим значением и ошибкой источника.
- Записать ключи и форматы `localStorage` и `sessionStorage` для истории чата, сессии агента, промптов, черновика из каталога и настроек инструментов. Подготовить тесты чтения ранее сохранённых данных.

**Приёмка.** Для всех семи страниц есть воспроизводимые скриншоты, данные и сценарии, которыми можно проверить результат переноса.

### 1. Подготовить основу React

- Добавить типизированный API-клиент. Сохранять текущие HTTP-методы, параметры, коды и форматы ответов. Различать ошибки сети, API и истекшую сессию, учитывая редиректы Gateway.
- Привязывать запрос к текущему набору фильтров. Отменять устаревшие запросы и исключать применение запоздавших ответов. Очищать таймеры при уходе со страницы.
- Вынести общие компоненты шапки, навигации, индикатора состояния и вкладок. Оставить локальное состояние страницы в React. Для сложных сценариев чата и редакторов описать переходы отдельными редьюсерами.
- Добавить модульные и компонентные тесты. Проверить маршруты, вход и возврат после авторизации в обоих режимах Gateway.

**Приёмка.** Общие компоненты совпадают с эталоном, работают с клавиатуры и помещаются на мобильном экране. Ошибки и гонки запросов воспроизводятся в тестах.

### 2. Перенести «Пульс сделок»

- Перенести воронку, карточки, вкладки «Сделки» и «Сводки», списки красных сделок и последних активностей, SVG-график давности активности.
- Вычислять порядок, видимость и подсветку блоков из `/api/view-state`. Сохранить активные ситуации и логику фильтра по умолчанию.
- Сохранить ручное и минутное автообновление. Привязать ответы списков и сводки к актуальной воронке.

**Приёмка.** Страница проходит сквозные и визуальные проверки без загрузки `static/app.js`. Возврат из соседней вкладки воспроизводит исходный вид. Запоздавший ответ по воронке A не перезаписывает данные воронки B.

### 3. Перенести «Пульс лидов» и «Сотрудники»

- Переиспользовать готовые компоненты аналитики. У лидов отдельно хранить общий пульс и конверсию по выбранной воронке. Сохранить красные лиды, SLA, графики и формат длительностей.
- У сотрудников сохранить портфель, список активностей, сводку и независимые фильтры сотрудников для списка и графика. При смене воронки пересчитывать доступные варианты и корректно обрабатывать исчезнувший выбор.

**Приёмка.** Каждый фильтр влияет на ту же область данных, что в legacy. Сохранены внешний вид, автообновление, пустые состояния и поведение при частичной ошибке.

### 4. Перенести AI Agent, каталог и отладчик запросов

- Вынести общие функции для сохранённых промптов, типизированных параметров SPARQL, представления результата и экспорта. Применять их по мере переноса страниц.
- Перенести AI Agent. Сохранить сессию, историю, прогресс по `request_id`, клавиатурную отправку, сохранённые промпты, Markdown и экспорт таблиц. Сбрасывать опрос прогресса при завершении, сбросе чата и уходе со страницы.
- Перенести каталог `/queries` и отладчик `/tools/queries` отдельными изменениями. Сохранить выполнение запросов через MCP, таблицу и JSON, скачивание, копирование, публикацию и перенос черновика из каталога. Привязать успешную проверку к конкретной версии запроса и параметров.

**Приёмка.** Проходит цепочка «ответ агента → сохранённый промпт → отладчик → публикация → запуск из каталога». Уже сохранённые в браузере данные открываются в обоих режимах.

### 5. Перенести «Онтологии»

- Разделить состояние открытого файла, несохранённых правок, опубликованной версии и предложения помощника. Сохранить предупреждение при уходе с несохранённым текстом.
- Перенести загрузку TTL, проверку, сохранение, публикацию, откат, статистику классов, карантин и восстановление. Сохранить проверки SHA, отпечатка графа и диалог подтверждения удаления.
- Сохранить проверку актуальности предложения помощника. Применение предложения заполняет редактор. Сохранение файла и публикация остаются отдельными действиями.

**Приёмка.** Проверены успешные операции, отмена, конфликт версии и повторное открытие файла. Контрактные тесты подтверждают прежнее разграничение прав на чтение и запись.

### 6. Завершить переход и проверить откат

- После переноса последней страницы убрать из React-сборки `html-react-parser`, адаптер запуска legacy-скриптов и зависимость от их глобальных объектов.
- Оставить исходный HTML/JS в режиме отката `GATEWAY_WEB_APP_ENABLED=0`. Проверить оба режима из собранного Docker-образа.
- Выполнить дымовые проверки Gateway, входа, навигации и ключевых операций на изолированном стенде. Отдельно проверить переключение с React на legacy и обратно.

**Приёмка.** Все семь страниц отрисовываются React и выполняют сценарии без старых контроллеров. При откате сохраняются URL, сохранённые данные и действующая сессия входа.

## Матрица сквозных тестов

| Страница | Сценарии Playwright |
| --- | --- |
| Пульс сделок | Первый вход, переход на соседнюю вкладку и возврат, Back/Forward. Воронка, два раскрываемых списка, сводка, порядок и скрытие блоков, обновление вручную и по таймеру, запоздавший ответ. |
| Пульс лидов | Карточки, красные лиды, SLA и длительности, графики общего пульса и конверсии. Смена воронки влияет на конверсию. Пустые выборки, пропуски на графике и ошибки. |
| Сотрудники | Портфель, список активностей и сводка. Независимые фильтры сотрудников, смена воронки, исчезновение выбранного сотрудника и запрос после сброса выбора. |
| AI Agent | Enter и Shift+Enter, прогресс и результат, отмена опроса при сбросе и переходе, восстановление сессии и истории. Лимит сохранённых промптов, вставка и удаление, Markdown, экспорт таблиц. |
| Каталог запросов | Запуск с параметрами и без них, типы и ошибки заполнения, таблица и JSON, CSV/XLSX, копирование, перенос в отладчик. Удаление с подтверждением, отменой и отказом API. |
| Отладчик запросов | Открытие сохранённого запроса и черновика, проверка и сохранение, предупреждение о несохранённых правках. Изменение текста или параметров сбрасывает результат прежней проверки для публикации. |
| Онтологии | Загрузка и открытие TTL, проверка, создание, сохранение, конфликт SHA, публикация, откат и статистика. Подтверждение и отмена удаления, карантин и восстановление. Применение предложения в редактор, устаревшее предложение и недоступность помощника. |

## Уровни проверки и порядок запуска

| Уровень | Покрытие |
| --- | --- |
| Модульные тесты | Даты, длительности, проценты, координаты и пропуски графиков, правила `view_profile`, параметры SPARQL, разбор ответов MCP, CSV с кириллицей и кавычками, форматы хранения и переходы состояния чата и редакторов. |
| Компонентные тесты | Загрузка, успех, пустой результат, частичная ошибка и ошибка API. Клавиатура и фокус во вкладках и фильтрах, Escape и возврат фокуса в диалогах, доступность кнопок редактора. Управляемые часы для таймеров и задержанные ответы для гонок. |
| Визуальные тесты | Сравнение со снимками legacy на трёх ширинах. Дополнительные кадры для раскрытых списков, сводок, результата запроса, ответа агента и диалога онтологии. При расхождении сохранять фактическое, эталонное и разностное изображения. Утверждать изменения эталона отдельно. |
| Контрактные тесты | Существующие Python-наборы Gateway, Auth, Analytics, Agent и Ontology. Расширить проверки на все 15 URL и псевдонимов в обоих режимах Gateway. Проверить загрузку JS/CSS, вход и возврат на исходный URL, истечение сессии, коды и форматы ответов. |
| Compose | Проверка готовности сервисов, собранных страниц и ассетов за Gateway, входа, навигации и отката. Для публикации запросов, TTL и восстановления использовать изолированные тестовые хранилища и собственные тома. |

Для каждого переноса в CI запускать сборку React, модульные и компонентные тесты, Playwright и Python-контракты на собранных файлах. Compose-прогон нужен перед выпуском. Браузерные тесты используют детерминированные данные. Отдельный интеграционный прогон отправляет запросы через реальный Gateway в изолированной среде.

Доступные команды из корня проекта:

```bash
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run test:unit
npm --prefix frontend run test:components
npm --prefix frontend run test:e2e
uv run --directory backend --locked python -m unittest discover -s tests -v
python tests/compose/react_smoke.py
```

В Windows команда `python tests/compose/react_smoke.py --contracts` выполняет Python-тесты в Linux, где доступен `fcntl`. Связанные тесты — [Playwright](../frontend/e2e/app.spec.ts), [Gateway](../backend/tests/test_gateway_service.py) и [маршруты legacy](../backend/tests/contracts/test_legacy_routes.py).

### Воспроизведение эталона

Playwright использует один браузер Chromium для React и legacy, одинаковые ответы из `mockApi`, время 25 ноября 2026 года, 12:00 по Москве, ширины 1440, 768 и 390 px и высоту 900 px. Обе версии используют системный стек шрифтов из `frontend/static/styles.css`. На Windows для прогона с установленным Edge можно задать `PLAYWRIGHT_CHANNEL=msedge`. Снимки первых экранов и состояний после действий сохраняются раздельно в `frontend/test-results/`. При расхождении в отчёт прикладывается разностное изображение.

| Действие | Запросы |
| --- | --- |
| Вход в сделки, смена воронки, ручное или минутное обновление | `/api/pulse` и `/api/view-state` с текущей воронкой. Запросы открытых списков и сводки повторяются при обновлении. |
| Раскрытие списка сделок или активностей, открытие сводки | `/api/red-deals`, `/api/recent-activities` и `/api/deal-activity-distribution` соответственно. |
| Вход в лиды или обновление | `/api/lead-pulse`, `/api/lead-conversion-trend` и `/api/view-state`. Воронка применяется к конверсии и состоянию вида. |
| Вход в сотрудников или обновление | `/api/pulse`, `/api/employee-recent-activities`, `/api/lead-employee-pulse` и `/api/view-state`. Воронка влияет на портфель и список активностей. Фильтр графика передаётся отдельно. |
| Отправка сообщения | `POST /api/agent`, опрос `/api/agent/progress?request_id=…` и запись времени запроса в `/api/agent/profile`. |
| Каталог и отладчик | `/api/published-queries` для каталога, публикации и удаления. `POST /api/agent/query` для выполнения SPARQL с параметрами. |
| Онтологии | `/api/ontologies` для списка, файлов, проверки, публикации и карантина. `/api/ontology-assistant` для конфигурации, предложения и проверки версии. |

Ноль в счётчике отображается числом. Пустой массив скрывает таблицу и включает сообщение о пустой выборке. У точки графика с отсутствующим значением образуется разрыв, длительность без значения отображается как «Нет данных». Ошибка источника отображается в соответствующем блоке.

| Хранилище | Ключи и формат |
| --- | --- |
| `sessionStorage` | `agentSessionId` — строка. `agentHistory` и `agentTranscript` — JSON-массивы объектов `{role, content}`, в видимом диалоге допускается `saved_query`. Старые `reactAgentSession` и `reactAgentHistory` переносятся однократно с отметкой `agentReactChatMigrated`. |
| `sessionStorage` | `agentPublishedQueryDraft` — JSON-объект `{id, title, query}`. |
| `localStorage` | `agentSavedPrompts` — JSON-массив объектов `{prompt, sparql}` или строк прежней версии. `crm-pulse-tools-admin-token` — строка. При открытии онтологий прежний `crm-pulse-ontology-admin-token` переносится в общий ключ. |

## Первый результат для приёмки

Зафиксировать эталоны и выпустить «Пульс сделок» первым. Принять страницу после совпадения скриншотов, проверки переходов и гонок между запросами и подтверждения, что все действия выполняются без загрузки `static/app.js`. Использовать эту страницу как образец для следующих дашбордов.
