# Управление онтологиями и графами классификации

Файлы `*.ttl` в этой папке — единственный источник аксиом. Редактор доступен на `/ontologies`. Для каждого slug файла `<slug>.ttl` сервер вычисляет граф `urn:bitrix24:ontology:<slug>`; путь и URI графа браузер не задаёт. В Turtle должен быть ровно один субъект `owl:Ontology` с этим URI.

## Администрирование

Задайте длинный секрет `ONTOLOGY_ADMIN_TOKEN` в окружении сервера. Введите его на странице управления; он остаётся только в памяти вкладки и передаётся как Bearer-токен. Без токена запись отключена. Изменяющие запросы также проверяют `Origin`. Сервер ограничивает Turtle и запрос до 256 KiB. Публикация доступна только при `RDF_BACKEND=graphdb`; используются `RDF_URL`, `GRAPHDB_REPOSITORY`, `RDF_USERNAME`, `RDF_PASSWORD` и `RDF_TIMEOUT`.

Порядок работы: открыть файл или загрузить `.ttl`, указать slug, проверить Turtle, сохранить, затем отдельно нажать «Опубликовать сохранённую версию». Сохранение атомарно заменяет файл после проверки SHA-256 и не меняет RDF. Публикация всегда читает файл с диска, заменяет только вычисленный именованный граф и проверяет совпадение содержимого с учётом blank nodes. При таймауте PUT сервер не повторяет запись автоматически.

В Docker Compose `./ontologies` подключается как постоянный writable volume, при этом root filesystem остаётся read-only. Контейнер работает под UID 10001; обеспечьте ему доступ к каталогу на хосте (например, `sudo chown -R 10001:10001 ontologies`). Локальный процесс должен иметь права записи на эту папку.

## Существующие файлы и URI

| Файл | URI графа | Назначение |
|---|---|---|
| `lead-classification.ttl` | `urn:bitrix24:ontology:lead-classification` | Классификация лидов |
| `deal-classification.ttl` | `urn:bitrix24:ontology:deal-classification` | Классификация сделок |
| `activity-classification.ttl` | `urn:bitrix24:ontology:activity-classification` | Классификация активностей |
| `user-classification.ttl` | `urn:bitrix24:ontology:user-classification` | Классификация сотрудников |

Эти файлы и URI сохранены. RDF-данные сущностей остаются в собственных графах; правила онтологий хранятся отдельно.
